# Mockingbird

Mockingbird imports an API contract and serves a running mock that answers with schema-valid responses generated by an LLM (or by a built-in faker when offline). This power connects its MCP server (`mockingbird mcp`), which exposes setup, LLM onboarding, the background server and the whole Admin API as tools.

## Onboarding

1. Install the binary if `mockingbird --version` fails:
   - macOS / Linux: `curl -fsSL https://raw.githubusercontent.com/rj-s-org/mockingbird/main/install.sh | sh` (installs to `~/.mockingbird/bin`; add it to `PATH`)
   - Windows: `irm https://raw.githubusercontent.com/rj-s-org/mockingbird/main/install.ps1 | iex`
2. Optional, for the full guides as steering files: `mockingbird agent install kiro`.
3. Run the `doctor` tool.

## Workflows

**Set up an LLM.** `list_llm_providers` → pick one (a provider whose key variable is already set; else OpenRouter or Google AI Studio; no key → offline). `init_config {provider, contracts}` for a new project or `configure_llm {provider, config}` for an existing one, then `test_llm {config, profile}`. Cloudflare AI Gateway needs `account_id` (or `CLOUDFLARE_ACCOUNT_ID`) and a Cloudflare token in `CF_AIG_API_KEY`; any other OpenAI-compatible endpoint is `provider: custom` with `base_url`, `model` and `api_key_env`. Never pass or store a key itself: the user exports the variable named in `secrets`.

**Serve.** `start_server {config: "mockingbird.yaml"}` (background, config watched), `server_status`, `server_logs`, `stop_server`. Data plane `http://127.0.0.1:8080`, console and Admin API `http://127.0.0.1:9090`, gRPC `127.0.0.1:50051`.

**Mock an API.** `import_contract {mock, source}` for OpenAPI, Swagger, GraphQL, .proto, WSDL or AsyncAPI files; documentation, HAR and Postman inputs become drafts (`approve: true` to take them, or review with `get_draft`, fix with `edit_draft`, accept with `approve_draft`). To run an app unchanged, `start_server {proxy: true}` and export `proxy_env` where the app runs. Then `call_mock {method, path, body, session}`; the result shows `x-mockingbird-source: llm | repaired | fallback`.

**Shape behaviour.** `put_scenario` (forced status, latency, fields, instructions; selected with the `X-Mockingbird-Scenario` header), `update_mock` (persona, LLM profile, chaos, limits), `seed_session` / `export_session` / `reset_session` (fixtures and state), `list_requests` (what clients sent).

**Self-host.** Docker (`ghcr.io/rj-s-org/mockingbird`), the Compose stack in `deploy/compose`, or the Helm chart `oci://ghcr.io/rj-s-org/charts/mockingbird`; turn on OIDC auth before sharing an endpoint.

## Troubleshooting

- Tools fail with "cannot reach the Admin API": no server runs; use `start_server`.
- Every response is `fallback`: the LLM fails or is slower than the profile timeout; run `test_llm` and read `hint`.
- 409 on a write: the resource is declared in `mockingbird.yaml`; edit the file.
