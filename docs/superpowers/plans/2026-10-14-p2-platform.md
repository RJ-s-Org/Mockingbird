# Mockingbird P2 Platform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the P1 single-process mock server into a persistent, manageable platform: SQLite or Postgres storage, an Admin REST API, scenarios, config-as-code with hot reload, extension traits for `mockingbird-cloud`, observability, and a container image.

**Architecture:**
- **New crates:**
  - `mb-ext`: extension traits and their defaults.
  - `mb-store`: control-plane entities and the `ControlStore` trait, with SQLite and Postgres implementations.
  - `mb-admin`: the Admin REST API.
- **Extended crates:**
  - `mb-state` gains SQL backends and a fallible API.
  - `mb-engine` gains scenarios and usage reporting.
  - `mb-protocols` gains admission, scenarios, request recording and degraded-state handling.
- **The `mockingbird` binary** gains:
  - a mock registry that hot-swaps runtimes when the store changes;
  - two listeners: the data plane on `:8080` and the admin/ops port on `:9090`;
  - config-file reconciliation with `--watch`;
  - admin client subcommands.

**Tech Stack:** P1 stack, plus:
- sqlx 0.9: runtime-tokio, rustls, sqlite, postgres, uuid, chrono, json, migrate
- arc-swap 1, utoipa 5 with axum integration (`utoipa-axum` if needed)
- metrics 0.24 and metrics-exporter-prometheus 0.18
- opentelemetry, opentelemetry_sdk and opentelemetry-otlp 0.33 (http-proto via reqwest), tracing-opentelemetry 0.34
- notify 8 and notify-debouncer-full (stable line), json-patch (merge patch), humantime-serde

**Spec:** `docs/superpowers/specs/2026-10-14-mockingbird-platform-design.md`. This plan covers the P2 row of §16. It implements §§3.2, 7 (admission, scenarios), 8, 9, 10 (profiles and fallback), 13 and 14 as they apply before auth (P3) and HA (P7).

## Global Constraints

- All P1 Global Constraints still hold: license, crate boundaries, no `unwrap()`/`expect()` in non-test code, clippy `-D warnings`, fmt, header names, and LLM env defaults.
- New crate names, exactly: `mb-ext`, `mb-store`, `mb-admin`. `mb-engine` must not depend on `mb-store`, `mb-admin`, axum or http. `mb-store` must not depend on axum.
- Workspace id is the constant `"default"` everywhere in P2. Multi-workspace and RBAC are P3.
- Ports: data plane `127.0.0.1:8080`, admin/ops `127.0.0.1:9090`. A non-loopback `--host` still requires `--insecure-no-auth`, and the rule covers both ports.
- Admin API base path `/api/v1`. OpenAPI document at `/api/openapi.json`. Every admin error is `application/problem+json` (RFC 9457).
- Ops endpoints on the admin port: `/healthz`, `/readyz`, `/metrics`. The data plane keeps `/__mockingbird/healthz`.
- Storage URLs:
  - `sqlite::memory:` (zero-config default)
  - `sqlite://<path>` (created if missing)
  - `postgres://…`
- Migrations live in `crates/mb-store/migrations/{sqlite,postgres}` and `crates/mb-state/migrations/{sqlite,postgres}`. They run at startup with `sqlx::migrate!`, which takes Postgres's advisory lock.
- Secret references: `env:NAME` or `file:/path`. A raw secret value is never stored, returned by the API, or logged. Vault and KMS backends are P7.
- Config precedence: `mockingbird.yaml` < `MB_*` env < CLI flags. Env names:
  - `MB_HOST`, `MB_PORT`, `MB_ADMIN_PORT`, `MB_STORAGE_URL`, `MB_ADMIN_URL`
  - P1 `MB_LLM_*`, which overrides the default profile
- File-managed resources have `source = file` and are read-only through the API (409 problem).
- Session id header value: 1–128 chars of `[A-Za-z0-9._-]`; anything else → 400 problem.
- Request log defaults: retention 1000 entries per mock; `redact_fields` (case-insensitive key match, anywhere in JSON) `["password","token","secret","authorization","apiKey","api_key"]` → value `"[redacted]"`.
- Postgres tests read `MB_TEST_POSTGRES_URL`. When it is unset they print `skipped: MB_TEST_POSTGRES_URL not set` and return. CI sets it through a `postgres:16` service, and `scripts/test-postgres.sh` starts a throwaway local server.

## Review Focus

1. **Hot reload while requests are in flight.** Swapping a mock's runtime (contract activation, config reload) must not fail requests already running, and new requests must see the new contract. Test: Task 8 `swap_during_inflight_requests`.
2. **A contract upload that fails to compile.** Return 422 with the importer's pointer, and leave the active version and the served mock unchanged. Test: Task 9 `bad_contract_upload_keeps_active_version`.
3. **The state store becomes unreachable at request time** (Postgres restart). The mock keeps answering statelessly, `/readyz` reports `degraded`, and a warning is logged with no 5xx. Tests: Task 7 `state_errors_degrade_to_stateless`, Task 10 `readyz_reports_degraded_state_store`.
4. **Secret leakage.** Profile endpoints return `secret_ref` and never the resolved value. The request log redacts configured fields. A provider error never logs the API key. Tests: Task 9 `profiles_never_return_secret_values`, Task 10 `request_log_redacts_fields`.
5. **Config/API ownership conflicts.** API mutation of a file-managed mock or profile → 409. Reconcile never deletes API-created resources, and a broken config reload keeps the previous state. Tests: Task 11 `file_managed_resources_are_read_only`, `reconcile_keeps_api_resources`, `invalid_reload_keeps_previous_state`.

Rules:
- `activate_contract_version` runs in one transaction. The previous `Active` version becomes `Approved`. Activating a `Draft` gives `Invalid`. It publishes `ControlChange::Mock`.
- Every mock, profile, scenario and contract mutation publishes the matching `ControlChange` (scenario changes publish `Mock`). The broadcast capacity is 256.
- `append_request_log` deletes that mock's rows beyond `retention`, but only once every 100 inserts (`id % 100 == 0`) so retention stays cheap.
- `Bundle` and JSON columns are stored as JSON text (SQLite) or `jsonb` (Postgres). Uuids are stored as text (SQLite) or `uuid` (Postgres).
- Uniqueness: `(workspace, name)` for mocks and profiles; `(mock_id, version)` and `(mock_id, name)` for versions and scenarios.

- `tests/conformance.rs` is a `pub async fn run_all(store: Arc<dyn ControlStore>)` suite, included by the per-backend test files with `#[path]`, so both backends run identical assertions.

```rust
pub struct SessionInfo { pub session: String, pub resources: usize, pub last_touched: DateTime<Utc> }
#[async_trait] pub trait StateStore: Send + Sync {
    async fn get(&self, s: &SessionKey, resource_type: &str, id: &str) -> Result<Option<StoredResource>, StateError>;
    async fn list(&self, s: &SessionKey, resource_type: &str, limit: usize) -> Result<Vec<StoredResource>, StateError>;
    async fn upsert(&self, s: &SessionKey, r: StoredResource) -> Result<(), StateError>;
    async fn delete(&self, s: &SessionKey, resource_type: &str, id: &str) -> Result<bool, StateError>;
    async fn reset(&self, s: &SessionKey) -> Result<(), StateError>;
    async fn sessions(&self, workspace: &str, mock: &str) -> Result<Vec<SessionInfo>, StateError>; // last_touched desc
    async fn export(&self, s: &SessionKey) -> Result<Vec<StoredResource>, StateError>;
    async fn seed(&self, s: &SessionKey, resources: Vec<StoredResource>) -> Result<(), StateError>;  // replaces session contents
    async fn ping(&self) -> Result<(), StateError>;
    fn subscribe(&self) -> broadcast::Receiver<StateChanged>;
}
// sql.rs
pub struct SqlStateStore { /* sqlx AnyPool-free: enum { Sqlite(SqlitePool), Pg(PgPool) } */ }
impl SqlStateStore { pub async fn connect(url: &str, ttl: Duration) -> Result<Self, StateError>; } // runs migrations; sweeps every 60s
pub async fn connect(url: &str, ttl: Duration) -> Result<Arc<dyn StateStore>, StateError>; // "memory" → MemoryStore, else SqlStateStore
```

- `StoredResource` derives `Serialize, Deserialize` (for export and seed).
- **Reads never create a session.** This fixes P1 deferred T7: `get`, `list` and `export` on an unknown session return empty without allocating. Only `upsert` and `seed` create one. Reads of an existing session refresh `last_touched`.
- `SessionKey.session` must hold a valid session id (per the Global Constraints). Validation lives in the protocol layer.
- Bus: in-process broadcast in both stores. The multi-node bus is P7.

Dockerfile:
- Builder stage `rust:1.97-bookworm`, which caches dependencies by building with a stub `main` first, then runs `cargo build --release -p mockingbird`.
- Runtime stage `gcr.io/distroless/cc-debian12:nonroot`, copying the binary to `/usr/local/bin/mockingbird`.
- `EXPOSE 8080 9090`, `ENTRYPOINT ["mockingbird"]`, `CMD ["--help"]`. The image does not default to listening publicly without auth; the README shows `serve --host 0.0.0.0 --insecure-no-auth`.

README: the config-file quickstart, the Admin API overview with the `/api/openapi.json` link, the CLI client, scenarios, Docker usage, the ops endpoints, and Postgres.
